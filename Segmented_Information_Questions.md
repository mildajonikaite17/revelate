# Questions by Behavioural Segment

## A — Public-Record Owner

1. Which published description best reflects your current responsibilities?
2. Is there anything in this sourced draft that conflicts with your published company information?
3. Which publicly announced initiative should this overview highlight?
4. **Sales:** Which publicly described customer segment should the profile emphasise?
5. **Product:** Which publicly documented product capability best represents your team's work?
6. **Engineering:** Which published technical topic should this overview reflect?
7. **HR:** Which publicly advertised learning or onboarding programme should the summary mention?
8. **Finance / operations:** Which published service or responsibility best represents your function?
9. **Marketing:** Which publicly stated message should the overview emphasise?
10. **Public sector:** Which published service best represents your unit's remit?
11. **Private sector:** Which public product or service should be highlighted in the organisation profile?
12. **Freelancer:** Which public portfolio project best represents the work you want this profile to describe?

## B — Governance Evaluator

13. What outcome would make this assessment useful to your team?
14. What information do you need about the organiser and intended use of answers before deciding whether to participate?
15. Which topics should be excluded from the assessment?
16. What kind of assessment output would be useful to your work?
17. **Manager:** Which team milestone would this assessment help you evaluate?
18. **Sales:** Which measure does your team use to judge progress toward its current commercial priority?
19. **Product:** Which criteria determine whether the next product milestone is ready to proceed?
20. **Engineering:** Which review criteria apply before the next release?
21. **HR:** How does your team assess whether its current learning activity is useful?
22. **Finance / operations:** Which part of the process your team is reviewing most needs improvement?
23. **Marketing:** Which audience is the next campaign intended to reach?
24. **Public sector:** Which service-improvement activity is your unit currently prioritising?
25. **Private sector:** Which dependency is most likely to affect your department's next deliverable?
26. **Freelancer:** What is the next deliverable in your current project?

## C — Gatekeeper / Verification-First Recipient

27. What organiser details would you need to verify before continuing?
28. Would you prefer a short plain-text outline before deciding whether to participate?
29. Which part of the proposed outline falls within your professional remit?
30. Which published source should be used for the relevant facts?
31. Once verification is complete, which specific professional problem would be useful for the example to address?
32. **Engineering:** Which publicly documented capability should the technical example cover?
33. **Product:** Which publicly documented product limitation should the example account for?
34. **HR:** Which published learning or careers resource should the outline use?
35. **Finance / operations:** Which public service description should the process example follow?
36. **Public sector:** Which published service description defines the scope of your unit's work?
37. **Freelancer:** Which published service description should the sample brief follow?
38. Would you prefer to pause the conversation until the requested verification is complete?
